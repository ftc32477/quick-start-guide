## 4. 占位与"留空"规则

- **不可见占位**：正文中用 HTML 注释，不渲染进 HTML/PDF：
  `<!-- TODO(I-09): 补 Pit 布置照片，来源：队长/Drive Team -->`
- **可追踪清单**：所有 TODO 同步登记到 `TODO.md`，包含：编号、页面/小节、需要什么、对应输入（I-01～I-18）、责任人、阻塞级别。
- **禁止编造**：查不到的规则数字、未实测的参数、没有的照片，一律不编；正文退化为通用描述 + 官方入口，并留 TODO。
- 草稿的 PDF 预览允许出现版面空白（例如图片位置），但**正式合入前必须清零 TODO 或转为"明确不再做"**。

## 5. 内容分级

| 级别 | 含义 | 处理方式 |
|---|---|---|
| A | 可直接起草（通识/结构/模板） | AI 起草 + 自检 |
| B | 需官方核实（规则/参数/奖项） | 查官方手册并注明版本/核查日期；不确定处留 TODO |
| C | 需团队素材（照片/实测/案例） | 文字先写到可接住素材，位置留 TODO |
| D | 需人工签字/授权（安全/公开尺度/母语审校） | 只起草，等待 I-13/I-14/I-18 |

## 6. 每章交付与审核

交付物：`<page>.md` 草稿 + `TODO.md` 更新 + 预览 PDF/HTML（`build_draft.py`）。

自检清单：

- [ ] 无遗漏 TODO（或全部在 `TODO.md` 登记）；
- [ ] 易变事实有官方链接 + 核查日期/手册版本；
- [ ] 术语与《附录》术语表一致；
- [ ] 图注编号、交叉引用、表格编号正常；
- [ ] `build_draft.py` 生成 HTML/PDF 无误；
- [ ] 与现有章节风格、文风一致。

人工审核：各组技术审校（I-13）→ 主编终审 → 通过后合入 `dev` 并进入翻译。

## 7. 预览命令

```bash
# 先生成 dist/images（草稿预览复用正式图片派生）
python3 build.py --channel dev
python3 drafts/build_draft.py /tmp/ftc-v2-draft
# 输出：/tmp/ftc-v2-draft/zh-hans/draft-preview.html 与 draft-preview.pdf
```

- 预览脚本不修改 `src/`、`PAGE_KEYS`、`dist/`。
- Chrome 无头打印依赖与正式 PDF 相同；若本机无 Chrome，只生成 HTML。
